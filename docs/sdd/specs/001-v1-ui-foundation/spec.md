# 001 · V1 UI 风格与信息层级

> 状态：Draft · 需要用户确认后实施

## 问题

V1 已具备完整教学闭环，但全局蓝紫渐变、多种课程颜色和同构卡片使信息层级趋于平均；当前任务、辅助资料与状态提示难以一眼区分。此前单页视觉稿没有复用 V1 的真实路由与任务流程，因此不能作为实现目标。

## 目标

- 在不改变 V1 路由、业务数据和交互闭环的前提下，建立清透紫视觉系统，并通过 V1 样式命名空间确保 V2 视觉不变。
- 让学生端在课程周历、Week 8、提交页清晰识别“当前处于什么状态、下一步做什么”。
- 让教师端复用同一设计语言，保持后台数据浏览效率。

## 范围

1. 全局 token 与 `AppShell`。
2. 入口页、学生课程周历、教学周详情、提交页与 AI 报告的层级优化。
3. 教师学情看板的 token 与表格/状态样式对齐。

## 范围外

- 不改动任何 `v2.*` 文件。
- 不改变课程周、模拟规则、AI 评分、游戏计算或 store 数据结构。
- 不新增后端、认证、真实文件存储。
- 不重写现有路由树或删除教学功能。

## 体验决策

- 冷白/浅蓝灰承担空间；墨黑承担重要数据；清华紫只代表当前任务与行动。
- V1 token 只在 `data-ui="v1"` 范围内生效；V2 继续使用既有根级 token。
- 首页是身份与当前学习入口，不是新建营销 Landing Page。
- 周历使用“当前 Week 8 主任务 + 历程概览”的层级；14 周数据仍完整可访问。
- Week 8 使用任务闭环视图，保留学习、练习、预检、仿真与批改入口。
- 提交页按状态阶梯呈现，避免所有按钮同时竞争。

## 验收条件

- 学生可从 `/` 进入 `/student`，并在首屏找到当前周与下一行动。
- 从 Week 8 可进入练习、提交、AI 助教和批改相关页面；既有链接不失效。
- 提交页的“预检 → 仿真 → AI 批改”状态与操作顺序清晰，原有模拟行为不变。
- 教师端导航和看板数据可用，视觉 token 与学生端一致。
- `/v2` 的主要背景、主按钮与导航在改造前后保持既有视觉 token，不因 V1 改造变化。
- 375px 与桌面宽度无横向溢出；主按钮、导航不折为两行。
- 正常文本与背景满足至少 4.5:1 对比度；状态不只用颜色表达，仍保留图标或文字标签。
- `npm run build` 与 `npm run lint` 通过。
