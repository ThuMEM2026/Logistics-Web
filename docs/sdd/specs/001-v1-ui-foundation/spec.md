# 001 · 智慧物流系统设计 · V1 UI 与任务优先体验

> 状态：Draft · 需要用户确认后实施

## 问题

V1 已具备完整教学闭环，但仍以“课程周历 → 知识 → 任务”的传统叙事为主，且全局蓝紫渐变、多种课程颜色和同构卡片使信息层级趋于平均。它没有充分表达蔡老师提出的“先做任务、暴露问题、AI 辅助提问、补知识、改方案、教师看过程”的课程改革逻辑。此前单页视觉稿没有复用 V1 的真实路由与任务流程，因此不能作为实现目标。

## 目标

- 在不改变 V1 路由、业务数据和交互闭环的前提下，建立清透紫视觉系统。
- 将网站主展示名称统一为《智慧物流系统设计》，并清楚说明当前是设施规划与物料搬运课程基础上的 Wafia Bakery 分拣专题。
- 让学生端在课程周历、Week 8、提交页清晰识别“当前处于什么状态、下一步做什么”。
- 将学生端首要叙事从“先浏览课程”调整为“先尝试任务，再获得针对性学习与反馈”。
- 让教师端复用同一设计语言，保持后台数据浏览效率。

## 范围

1. 全局 token 与 `AppShell`。
2. 入口页、学生课程周历、教学周详情、AI 助教、提交页与 AI 报告的层级优化。
3. 教师学情看板的 token 与表格/状态样式对齐。
4. 其余 V1 页面只继承全局 token，不重构布局；其功能与导航必须保持可用。

## 范围外

- 不新增 V2 路由或游戏展示；游戏平台后续独立处理。
- 不改变课程周、模拟规则、AI 评分、游戏计算或 store 数据结构。
- 不新增后端、认证、真实文件存储。
- 不重写现有路由树或删除教学功能。
- 不在本规格内建设独立游戏平台、真实 RAG、真实文件解析、真实仿真服务或新增过程数据持久化。

## 体验决策

- 冷白/浅蓝灰承担空间；墨黑承担重要数据；清华紫只代表当前任务与行动。
- 网站主标题为“智慧物流系统设计”；“设施规划与物料搬运”作为课程基础说明，“AI+物流网络规划课程教学闭环平台”作为项目说明。
- 首页是身份与当前任务入口，不是新建营销 Landing Page；“本科课程”说明实际学习者，“清华 MEM 共创”说明项目来源，不能混作同一用户身份。
- 周历使用“当前 Week 8 主任务 + 历程概览”的层级；14 周数据仍完整可访问，学生可先开始尝试，再按问题回到知识资源。
- Week 8 使用任务闭环视图，按“初次尝试 → AI 提问 → 补充学习 → 预检与仿真 → AI 反馈 → 修改”组织既有入口。
- AI 助教以当前任务、目标、约束、已有尝试为上下文组织提问，强调帮助学生问清问题而非直接代答。
- 提交页按状态阶梯呈现；学生端明确展示已有的文件、仿真、批改记录，教师端据此阅读过程性证据。完整跨会话过程持久化另立规格。

## 验收条件

- 从 `/` 到学生端的主标题显示“智慧物流系统设计”；课程基础、项目来源与当前案例专题的层级表述不冲突。
- 学生可从 `/` 进入 `/student`，并在首屏找到当前周、一次初步尝试的入口与下一行动；“先尝试”进入 Week 8 真实任务，不以游戏作为主入口。
- 从 Week 8 可进入练习、提交、AI 助教和批改相关页面；既有链接不失效。
- AI 助教从 Week 8 进入时可见当前任务上下文与提问提示，且不会承诺代替学生完成方案。
- 提交页的“预检 → 仿真 → AI 批改”状态与操作顺序清晰，原有模拟行为不变。
- 教师端导航和看板数据可用，视觉 token 与学生端一致。
- AI 助教、案例库、共创工坊、闯关地图与我的提交页面在 token 变更后仍可进入、可阅读、可完成原有交互；游戏不作为网站主叙事。
- 375px 与桌面宽度无横向溢出；主按钮、导航不折为两行。
- 正常文本与背景满足至少 4.5:1 对比度；状态不只用颜色表达，仍保留图标或文字标签。
- `npm run build` 通过；`npm run lint` 不新增超出当前已记录 Prettier 基线的问题，基线问题另建规格处理。
