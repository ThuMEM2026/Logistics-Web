# Constitution · Logistics_MEM V1

> 状态：Active · 最后更新：2026-07-21

## 1. 产品边界

- V1 是面向本科《智慧物流系统设计》课程的教学平台，不是营销落地页；设施规划与物料搬运是其课程基础，Wafia Bakery 分拣是当前教学专题。
- 学生的主闭环是：课程周历 → 教学周 → 学习/练习 → 提交 → 仿真 → AI 反馈 → 修改。
- 教师的主闭环是：学情看板 → 案例与变量 → 复核与审核 → 评分规则。
- V2 展示源码已移除；后续游戏能力必须作为独立平台与独立规格处理，不回流为本项目的 V2 路由。

## 2. SDD 优先级

1. 本宪法与安全约束。
2. 已批准规格包中的 `spec.md`。
3. 已批准规格包中的 `plan.md` 与 `tasks.md`。
4. `context/` 中的可复用事实与经验。
5. 代码中的当前实现。

代码与已批准规格冲突时，先更新规格或显式记录偏差，不能静默偏离。

## 3. 规格包最低要求

每个 `specs/NNN-name/` 必须包含：

- `spec.md`：目标、用户、范围、非目标、用户流、验收条件；
- `plan.md`：文件级改动、依赖、风险、验证；
- `tasks.md`：按顺序执行且可验收的任务。

涉及视觉变更时，规格还必须说明设计 token、组件状态和移动端边界。

## 4. 体验原则

- 清透紫只作识别、当前状态与主行动；不作为大面积背景或无语义装饰。
- 冷白、浅蓝灰、墨黑承担阅读与结构；成功、风险、错误只服务语义状态。
- 同一操作在各学生页面中保持同一标签、位置逻辑与状态反馈。
- 首页与课程周历优先呈现“现在要做什么”，而不是平铺介绍所有能力。
- Week 8 是当前关键闭环，不能为了视觉简化而删除预检、仿真、批改证据链。

## 5. 实施与验证

- 不删除生产路由、课程数据或游戏逻辑，除非规格得到明确批准并列出删除范围。
- 视觉调整优先复用 Tailwind token 与共享 `AppShell`，避免单页硬编码体系。
- 每次实现至少验证：构建、关键学生路径、关键教师路径、375px 与桌面宽度。
- 发现的稳定经验写入 `context/patterns/`；失败原因写入 `context/pitfalls/`。

## 6. 归档

规格在验收完成后移入 `archive/`。归档内容只追加，不改写历史决策；如需改变历史结论，创建新规格说明取代关系。
