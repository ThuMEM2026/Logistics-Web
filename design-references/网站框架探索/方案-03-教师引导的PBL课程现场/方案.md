# 方案 03 · 教师引导下的 PBL 课程现场

> 状态：当前推荐，待用户确认后写入下一份 SDD 规格并实施。

## 课程定位

这是对清华本科《智慧物流系统设计》课程的教学改革探索。课程使用 PBL，将 AI、RAG 增强知识库、教师数字人分身与 Vibe Coding 纳入教学过程，而不是在传统课程外增加几个工具页。

## 教学关系

PBL 在这里由教师发起和编排，而非完全由学生自主推进。

```text
教师设定真实情境、问题边界、约束与阶段问题
→ 学生小组分析、尝试与讨论
→ AI / 教师数字人根据课程 RAG 知识库答疑、追问与支撑
→ 教师从学生过程和共性困惑中决定课堂介入
→ 学生使用 Vibe Coding 共创教学工具、动画、仿真或 Agent
→ 课堂共享、互评、方案修订与课程沉淀
```

## 平台空间

### 1. 本周 PBL 现场

学生进入的第一层。展示老师提出的案例情境、阶段问题、任务边界、已进行到的探究位置，以及由教师安排的下一步；不以行政周历或提交清单作为主视觉。

### 2. 探究与 AI 支撑

学生可带着当前任务、已有尝试和具体卡点进入 AI 助教 / 教师数字人。RAG 知识库未来应覆盖任务书、课件、案例材料、仿真规则、评分规则、典型误区和经教师确认的共创成果。

AI 的职责：解释、追问、指出应核查的证据和推荐相关知识；不直接替学生完成方案。

### 3. Vibe Coding 共创

学生将真实学习痛点转化为可复用的教学资产：概念动画、检查器、训练工具、仿真辅助、Prompt 或 Agent。教师审核、推荐并在后续课堂中复用这些成果。

### 4. 课程旅程

14 周保留为课程的结构、前置知识和阶段性回顾，而不是首页的主叙事。课程地图应显示阶段、开放状态、当前问题和与当前探究相关的知识支撑。

### 5. 教师课堂洞察

教师端优先回答：学生在问什么、哪些关键判断出现分叉、哪些知识误区反复出现、哪些共创成果值得带入课堂。提交与仿真记录是洞察依据，不是单纯监管指标。

## 导航建议

学生端以“本周现场、课程旅程、共创工坊、我的探究”为主；AI 助教应在各个任务和资料语境内可达，而不是只作为一个孤立的目的地。

教师端以“课堂洞察、案例与任务、知识库与数字人、共创审核”为主；具体的评分规则、变量和复核可进入二级工具层。

## 验收标准

- 学生首次进入能理解本周由老师提出的真实问题和自己该做什么；
- 学生从任一探究阶段进入 AI 时，能看到任务语境和“已有尝试 / 当前卡点”的提问引导；
- Vibe Coding 共创可被理解为课程产出与学习支撑，不是孤立兴趣社区；
- 教师能基于学生过程组织课堂讨论与介入；
- 现有周历、文件提交、仿真、AI 反馈、案例库与工坊功能均可保留并进入正确的位置。
